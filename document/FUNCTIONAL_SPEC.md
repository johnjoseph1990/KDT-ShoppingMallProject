# 📋 기능 명세서 (Functional Spec)

> Sprint Day 1 산출물. ERD는 [`ERD.md`](./ERD.md), 일정은 [`SPRINT_PLAN.md`](./SPRINT_PLAN.md) 참고.
> 우선순위: **P0** = 없으면 과제 미달 / **P1** = 과제 요구사항 / **P2** = 여유 시 확장

## 1. 사용자 흐름 (핵심 시나리오)

```
[비회원]
  상품 목록 → 상품 상세 → (회원가입/로그인 유도)

[회원]
  로그인 → 상품 목록/검색/필터 → 상품 상세 → 장바구니 담기
        → 장바구니 확인 → 주문하기 → 모의 결제 → 주문 완료
        → 주문 내역 확인 / 받은 상품에 리뷰 작성

[관리자]
  로그인(ADMIN) → 관리자 페이지 → 상품 등록/수정/삭제(재고 포함)
              → 주문 목록 → 주문 상태 변경 (결제완료 → 배송중 → 배송완료)
```

## 2. 기능 목록

### 회원 (Day 2)
| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| M-1 | 회원가입 | 이메일·비밀번호·이름, 비밀번호 BCrypt 해시 저장 | P0 |
| M-2 | 로그인/로그아웃 | 인증 성공 시 세션 또는 JWT 발급 | P0 |
| M-3 | 권한 분리 | USER / ADMIN 역할, 관리자 기능은 ADMIN만 접근 | P0 |

### 상품 (Day 2)
| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| P-1 | 상품 목록 조회 | 페이징, 이미지(URL)·이름·가격 표시 | P0 |
| P-2 | 상품 상세 조회 | 설명·재고·리뷰 목록·평균 별점 포함 | P0 |
| P-3 | 상품 등록/수정/삭제 | 관리자 전용, 이미지는 URL 입력 | P0 |

### 장바구니 · 주문 · 결제 (Day 3)
| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| O-1 | 장바구니 담기/삭제/수량변경 | 회원 전용 | P0 |
| O-2 | 주문 생성 | 장바구니(또는 바로구매) → 주문 + 주문상세 생성, 당시 가격 스냅샷 | P0 |
| O-3 | 모의 결제 | 결제 요청 → 성공/실패 판정 → payment 기록 + 주문 상태 변경 | P1 |
| O-4 | 주문 상태 흐름 | ORDERED → PAID → SHIPPING → DELIVERED, CANCELED는 ORDERED·PAID에서만 가능(배송 시작 후 취소 불가) | P1 |
| O-5 | 재고 차감 + 동시성 | 주문 시 재고 차감, 낙관적 락(@Version)으로 초과 판매 방지 | P1 |
| O-6 | 내 주문 내역 조회 | 회원 본인 주문 목록/상세 | P0 |

## 4. 잘라내기 기준 (일정 지연 시)

시간이 부족하면 이 순서로 축소한다 (전체 흐름은 반드시 유지):
1. R-6 (키워드 추천) → 같은 태그 상품 나열로 단순화
2. P-4 (검색) → 생략
3. O-3 (모의 결제) → 주문 즉시 PAID 처리로 단순화 *(최후의 수단)*
