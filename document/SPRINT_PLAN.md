# ⚡ 1주 스프린트 계획 (Sprint Plan) — 실제 제출용

> **마감:** 1주일 (오늘 기준 2026-07-11 시작)
> **전략:** AI 페어 프로그래밍 — AI가 코드를 주도 작성하고, 학습자는 **각 단계마다 "이 코드가 무엇을 하는지" 이해하며 따라간다.**
> **깊은 학습:** 제출 후 [`LEARNING_PLAN.md`](./LEARNING_PLAN.md)(16~20주)로 다시 진행
> **스택:** Spring Boot + Spring Data JPA + Spring Security / React + Vapor / H2(개발) → PostgreSQL(배포) / AWS

## 📏 확정된 범위 (Scope 결정사항)

| 항목 | 결정 | 이유 |
|------|------|------|
| 결제 | **모의 결제** (가짜 결제 단계: 요청→성공/실패→주문 상태 변경) | 과제의 "결제 흐름 연결" 충족 + 외부 연동 리스크 제거 |
| 상품 이미지 | **이미지 URL만 저장** (파일 업로드 없음) | 업로드 구현 없이 이미지 있는 쇼핑몰 완성 |
| DB | 개발은 H2, **배포 시 PostgreSQL** | 로컬 설치 부담 없이 속도 확보 |
| 동시성 재고 | JPA **낙관적 락(@Version)** 최소 구현 | 과제 요구 충족, 1주 내 구현 가능한 수준 |
| 주문 취소 시점 | **배송 시작(SHIPPING) 후 취소 불가**, ORDERED·PAID 상태에서만 취소 가능 | 원격 브랜치(Day 4~5 작업)와 로컬 브랜치(Day 3)가 서로 다른 규칙으로 병렬 개발되어 병합 시 충돌 → 배송 중 취소를 막는 쪽으로 통일(2026-07-13) |

## 📅 일자별 계획

> ✋ = 학습자가 멈춰서 이해하고 넘어가야 하는 체크포인트

### Day 1 — 설계 + 환경 구축
- [x] 기능 명세서 작성 (화면 흐름 + 기능 우선순위) → `document/`
- [x] ERD 설계 (회원·상품·주문·주문상품·리뷰) → `document/`
- [x] JDK + Node.js 설치, Spring Boot / React 프로젝트 생성
- [x] `git init` + GitHub 저장소 연결 + 첫 커밋
- ✋ **이해 체크:** ERD의 테이블 관계(1:N)를 자기 말로 설명할 수 있는가

### Day 2 — 백엔드: 상품 CRUD + 회원/인증
- [x] 상품 엔티티·CRUD API (이미지 URL 필드 포함)
- [x] 회원가입 / 로그인 (Spring Security + 비밀번호 암호화, 세션 또는 JWT)
- [x] 사용자/관리자 권한(Role) 분리
- ✋ **이해 체크:** 요청이 Controller→Service→Repository→DB로 흐르는 경로를 따라가 봤는가

### Day 3 — 백엔드: 주문 + 모의 결제 + 재고
- [x] 장바구니 → 주문 생성 → 주문 상태 흐름 (주문완료→배송중→배송완료 등)
- [x] **모의 결제** 단계 연결 (결제 요청 → 성공/실패 → 상태 반영)
- [x] 재고 차감 + 낙관적 락으로 동시 주문 처리
- ✋ **이해 체크:** "재고 1개에 주문 2건"이 어떻게 막히는지 설명할 수 있는가

### Day 4 — 백엔드: 리뷰·추천 + 관리자
- [x] 리뷰 작성/조회/삭제 + 별점 평균 계산
- [x] 별점 정렬, **키워드·태그 필터링**, **베스트 상품 섹션** API
- [x] 관리자: 상품 관리, 주문 내역 조회, 주문 상태 변경
- ✋ **이해 체크:** 별점 평균이 어느 쿼리에서 계산되는지 찾아봤는가

### Day 5 — 프론트: React + Vapor 화면 조립
- [x] 상품 목록/상세, 회원가입/로그인, 장바구니/주문, 리뷰, 관리자 화면
- [x] Vapor 컴포넌트로 UI 구성 (https://design.vapor.codes/)
- ✋ **이해 체크:** 화면 하나(상품 목록)에서 fetch → state → 렌더링 흐름을 따라가 봤는가

### Day 6 — 통합 테스트 + 배포

- [x] 예외 케이스 테스트 (재고 부족, 비로그인 접근, 잘못된 입력 등)

1. **막히면 그 기능을 축소하고 전체 흐름을 지킨다.** 하루 이상 지연되는 기능은 최소 구현으로 강등.
2. **매일 커밋.** 하루가 끝나면 그날 결과물이 GitHub에 있어야 한다.
3. **이해 체크(✋)는 건너뛰지 않는다.** 코드를 다 이해하진 못해도, 각 날의 체크 질문 하나는 답할 수 있어야 발표·질문 대응이 가능하다.
