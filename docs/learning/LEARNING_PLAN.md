# 📚 학습 계획 (Learning Plan)

> ⚠️ **역할 변경 (2026-07-11):** 과제 마감이 1주일로 확인되어, **실제 제출은 [`SPRINT_PLAN.md`](../../document/SPRINT_PLAN.md)(1주, AI 페어)로 진행**합니다.
> 이 문서는 **제출 후 처음부터 다시 깊게 배우는 장기 학습 계획**으로 사용합니다. 내용은 그대로 유효합니다.

> **대상:** Java / Spring / 프론트엔드를 처음 시작하는 학습자
> **프론트엔드 선택:** **React** (백엔드 REST API + 별도 React 앱 구조)
> **UI 도구:** **Vapor (goorm 디자인 시스템)** — React 컴포넌트 라이브러리, 문서 → https://design.vapor.codes/
> **DB:** **PostgreSQL** (학습 초반은 H2로 시작 → Phase 8에서 PostgreSQL로 전환)
> **전체 예상 기간:** 약 16~20주 (React 학습이 포함되어 Thymeleaf 방식보다 길다)

## 🎯 이 계획을 관통하는 3가지 원칙

### 1. 한 번에 새로운 것 하나만 배운다
셋 다 처음인 상태에서 Java + Spring + JavaScript + React를 동시에 배우면,
에러가 났을 때 **원인이 어디인지조차 구분이 안 됩니다.**
→ 그래서 **백엔드를 먼저 끝까지 익히고**, 그 다음 프론트로 넘어갑니다.

### 2. 수직 슬라이스 (Vertical Slice)
기능을 넓게 나열하지 않고, **상품(Product) 하나**로
`요청 → Controller → Service → Repository → DB → 응답` 전 계층을 관통합니다.
폭이 아니라 깊이. 이 한 조각을 이해하면 나머지는 **같은 패턴의 반복**입니다.

### 3. React는 "예쁜 화면"이 아니라 "연결"부터
React를 배우는 첫 목표는 쇼핑몰 디자인이 아니라,
**백엔드가 준 상품 목록 JSON을 React 화면에 한 번 띄우는 것**입니다.
이 순간이 당신의 **첫 풀스택(frontend ↔ backend) 연결**입니다.

---

## 🧱 왜 React는 "별개의 앱"인가 (먼저 이해하고 갈 것)

```
[ React 앱 ]  ←── JSON(데이터) ──→  [ Spring API 서버 ]  ←→  [ DB ]
 화면 담당                            데이터·로직 담당
 (JavaScript)                         (Java)
 별도 프로젝트 / 별도 실행             별도 프로젝트 / 별도 실행
```

- 둘은 **서로 다른 프로그램**이고, 각자 따로 실행됩니다.
- 둘 사이엔 화면(HTML)이 아니라 **JSON 데이터**만 오갑니다.
- 그래서 백엔드는 "화면"을 만들 필요가 없고, **API(데이터를 주는 창구)**만 잘 만들면 됩니다.
- 이 구조를 모르면 Phase 4부터 계속 헷갈리니, 이 그림을 기억해 두세요.

## 🎨 Vapor는 어디에 들어가는가 (과제 필수 도구)

**Vapor**(goorm 디자인 시스템)는 새로운 언어나 프레임워크가 **아니라**,
React 위에서 **가져다 쓰는 "미리 만들어진 UI 부품 상자"**입니다.

```
Vapor 없이:   <button style="...색·둥글기·여백 직접 지정...">담기</button>
Vapor 사용:   <Button color="primary">담기</Button>   ← 이미 완성된 부품
```

- Vapor는 **React 컴포넌트**라서, React 앱이 아니면 쓸 수 없습니다. → **React 선택과 정확히 맞물립니다.**
- 따라서 **Vapor를 React보다 먼저 배울 수는 없습니다.** 순서는 항상 `React 기초 → Vapor 적용`.
- 학습 부담을 늘리는 "큰 것"이 아니라, 프론트를 **더 쉽게** 만들어주는 도구입니다.
- 공식 문서: https://design.vapor.codes/

> **적용 방법:** Phase 3에서 *순수 React*로 화면을 먼저 만들어 보고(props·state·fetch 이해가 목적),
> 그게 되면 그 화면의 버튼·입력창·목록을 **Vapor 컴포넌트로 교체**합니다. 이후 Phase 4~8은 계속 Vapor로 조립합니다.

## 🗺️ 단계별 계획

> 각 Phase의 **"됐다"의 기준**을 실제로 눈으로 확인하고 넘어갑니다. 안 되면 다음으로 가지 않습니다.

### 🟦 1부. 백엔드 먼저 (화면 없이)

| Phase | 기간 | 새로 배우는 것 | 만드는 것 | "됐다"의 기준 |
|-------|------|----------------|-----------|---------------|
| **0. 기초 체력** | 1~2주 | Java 문법 + 객체지향(OOP), 웹 동작 원리(HTTP, JSON) | Spring Boot "Hello World" 서버 | 브라우저에 내 서버가 준 글자가 뜬다 |
| **1. 첫 수직 슬라이스** | 1~2주 | JPA 엔티티, Repository, H2 DB *(임시 — 최종은 PostgreSQL)* | 상품 목록 **조회 API** (GET) | Postman으로 상품 목록이 JSON으로 온다 |
| **2. 백엔드 CRUD 완성** | 2주 | REST API 설계, Swagger | 상품 등록/수정/삭제 API | Postman에서 상품을 추가·수정·삭제할 수 있다 |

> 🔑 **여기까지가 1차 관문.** 화면은 하나도 없지만, "요청이 DB까지 갔다 온다"를 몸으로 이해한 상태.

### 🟩 2부. 프론트엔드 입문 (React 연결)

| Phase | 기간 | 새로 배우는 것 | 만드는 것 | "됐다"의 기준 |
|-------|------|----------------|-----------|---------------|
| **3. JS + React 기초** | 2~3주 | JavaScript 필수 문법, React(컴포넌트·props·state·useEffect), fetch, CORS → 그 뒤 **Vapor 컴포넌트** 적용 | 상품 목록을 보여주는 React 화면 (순수 React → Vapor로 교체) | **백엔드 API의 상품 목록이 React 화면에 뜬다** ← 첫 풀스택! |

> 🔑 **여기가 두 번째 관문이자 가장 큰 고비.** 이 화면 하나만 성공하면 나머지 기능은 "같은 연결의 반복"입니다.

### 🟨 3부. 기능을 하나씩 (백엔드 API + React 화면을 함께)

| Phase | 기간 | 새로 배우는 것 | 만드는 것 | "됐다"의 기준 |
|-------|------|----------------|-----------|---------------|
| **4. 회원 & 인증** | 2~3주 | Spring Security, 비밀번호 암호화, JWT 토큰 | 회원가입 / 로그인 / 로그아웃 | 로그인해야만 볼 수 있는 페이지가 생긴다 |
| **5. 주문 흐름** | 2주 | 엔티티 연관관계, 주문 상태 관리 | 장바구니 → 주문 생성 → 상태 변경 | 상품을 담아 주문하면 주문 내역이 남는다 |
| **6. 재고 & 관리자** | 2주 | 트랜잭션, **동시성(락)**, 권한 분리 | 재고 차감, 관리자 페이지 | 재고가 정확히 줄고, 관리자가 주문을 관리한다 |
| **7. 리뷰 & 추천** | 1~2주 | 집계(별점 평균), 정렬·필터 쿼리 | 리뷰 CRUD, 별점 정렬/필터 | 별점순 정렬·태그 필터가 동작한다 |

## ⚠️ React를 골랐기에 특히 조심할 것

- **Phase 0~2를 건너뛰고 화면부터 만들고 싶은 유혹**이 가장 큽니다. 참으세요. 백엔드 API가 없으면 React가 불러올 데이터도 없습니다.
- **JavaScript를 대충 넘기고 React로 직행하지 마세요.** React는 결국 JavaScript입니다. 배열 `map`, 함수, `fetch` 정도는 확실히 하고 넘어가야 합니다.
- **막히면 "기능 하나를 끝까지"로 도망치세요.** 여러 기능을 반쯤 만들어 두면 뭐가 되고 안 되는지 알 수 없습니다. 상품 하나라도 백엔드→React까지 완성해 보는 게 백 개의 반제품보다 낫습니다.

## ✅ 이번 주에 할 일 (지금 시작점)

계획은 시작하지 않으면 의미가 없습니다. **Phase 0의 첫 걸음**만 콕 집어 드립니다:

1. JDK(자바) 설치 + IntelliJ에서 Java 파일 하나 실행해 `System.out.println("Hello")` 출력해 보기
2. [start.spring.io](https://start.spring.io) 에서 Spring Boot 프로젝트 생성 (의존성: Spring Web, Spring Data JPA, H2 Database, Lombok)
3. 만든 프로젝트를 실행해서 서버가 뜨는지 확인 (에러가 나도 괜찮습니다 — 그 에러를 읽는 것부터가 학습입니다)

> 이 세 개가 되면, Phase 0의 절반은 끝난 겁니다.
